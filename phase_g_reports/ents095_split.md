## MHLib profiles — what "main size" means and which field moves in lockstep

Profiles: `src/main/resources/data/orespawn/multihitboxlib/hitbox_profiles/{ant_robot,spider_robot,the_queen}.json`. Each has a `"main-hitbox": { "collidable", "canReceiveDamage", "size": [w, h] }` block (codec `MainHitboxConfig`, `de/dertoaster/multihitboxlib/entity/hitbox/MainHitboxConfig.java:9-21`, field name `size`, default `[0,0]`). `main-hitbox.size` is the parent entity's own AABB — MHLib's `EntityEventHandler.onEntitySizeEvent` (`de/dertoaster/multihitboxlib/EntityEventHandler.java:28-38`) answers NeoForge's `EntityEvent.Size` with `EntityDimensions.scalable(size.x, size.y)` whenever the entity's profile resolves and `size != [0,0]`, so it silently overrides both the EntityType `.sized` and any `getDefaultDimensions` override. **The field that must move in lockstep with the Java dims is `main-hitbox.size`** (the ENT-S-088 'Size-hook law' written into spider_robot.json's comment). The `parts[].box.size` entries are the sub-part boxes and are NOT part of the main size.
