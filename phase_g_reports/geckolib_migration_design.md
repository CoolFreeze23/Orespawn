## 2. Tiering proposal

Tier is assigned per model rig, while hitbox profiles and artist folders are
assigned per registry name. That distinction matters for shared rigs: `ModelAlien`

## 3. Visual-parity decision

The unresolved choice is whether a harness-proven GeckoLib renderer replaces its
classic renderer outright, or whether both ship behind
`modelStyle = GECKOLIB|CLASSIC`.

Recommendation: **replace outright, one entity slice at a time, only after the
independent geometry, fixed-phase animation, and pixel-diff legs all pass and the
owner accepts the capture set.** A failing or disputed species remains on its
classic renderer; it does not get tuned blind. Git history and the retained source
provide rollback without making every shipped client maintain two renderer
registrations, two model/layer paths, divergent feature renderers, duplicate test
matrices, and potentially both model trees resident in memory.

A runtime gate is safer only if the owner wants classic presentation to remain a
permanent player feature, not merely a migration fallback. If selected, the gate
must cover renderer registration, feature layers, scale transforms, culling,
textures, and resource reload—not just `getModelResource()`—and every visual test
must run in both styles. The game-logic classic/modern law remains unchanged under
either visual ruling.

The future parity gate must be harness-first and non-self-referential:

1. Bake the live vanilla `LayerDefinition` and independently compute its bind-pose
   world-space cube corners; compare those against separately evaluated geo bones.
2. Capture deterministic A/B frames at bind pose and fixed animation phases with
   fixed entity state, yaw, light, seed, camera, and renderer scale.
3. Sample Java `setupAnim` rotations independently at `0`, `T/4`, `T/2`, and
   `3T/4` and compare against evaluated clip transforms.
4. Stop and present any mismatch. Never adjust an output until it resembles the
   same output generated by the tool being tested.

## 4. Performance budget and measurement

GeckoLib evaluates bones and controllers each rendered frame; the current vanilla
models mutate already-baked `ModelPart` trees. With 100+ species, bone count,
controller count, translucent passes, MHLib part alignment, allocations, and
off-screen culling can all matter. Tier 1 also adds server tick/network cost that
an FPS-only test would miss.

Recommendation: add a repeatable benchmark scene to the future G1 harness before
batch work. On the same machine, JDK, JVM flags, resolution, render distance,
graphics settings, camera path, and fixed seed, compare classic and candidate in
these scenes:

- 100 copies of the converted species in view, with a fixed walking/attack state;
- 100 mixed species representative of the final tier distribution;
- the largest Tier-1 boss alone and ten copies, with every synced part active;
- an off-screen control to expose regressions from forced culling and controller
  work that continues when not visible.

Warm each scene for 60 seconds, record five 120-second runs, and report median and
p95 frame time (milliseconds), 1% low FPS, client CPU, allocation/GC rate, GPU
frame time where available, server MSPT/p95, MHLib packets per second, and part
count. Proposed acceptance budget: no more than 10% median-frame regression and no
more than 2 ms p95-frame regression in the 100-mob mixed scene, while server p95
stays below 50 ms with no sustained packet growth. A species that misses stays on
the classic renderer pending an owner ruling; aggregate results are measured again
after each 10–20-entity batch because individually cheap controllers can sum badly.

## 5. Animation conversion policy

The inventory buckets are migration-risk classes, not claims that every source
contains only one formula. The highest-risk behavior wins the row. Every future
clip's `SPEC.md` must quote its source method/line and transcribe the formula and
constants in plain language.

### Static

Convert only the bind rig. Do not invent breathing, hovering, or idle noise. If a
controller API requires a clip, use a zero-length/identity presentation whose
absence is mechanically verified; otherwise omit the controller. Tier 3 is the
default destination.

### Simple cyclic

For `base ± cos(ageInTicks * f + phase) * A` (and sine equivalents), derive the
natural period `T_ticks = 2π / |f|`, convert to seconds at 20 ticks/s, sample a
complete period including extrema and every source phase offset, and set the clip
to `loop: true`. Record `base`, `f`, `phase`, `A`, sample rate, and interpolation
mode next to the clip. The independent animation leg evaluates both formula and
clip at the four cardinal phases plus intermediate points; it must not import the
conversion routine.

### Gait-scaled

`limbSwingAmount` changes amplitude per tick, so a fixed-amplitude baked clip is
not equivalent. The ANIM-001 lesson is explicit: movement speed changes amplitude,
not the source frequency. Recommendation by tier:

- Tier 2: artist-editable idle/walk clips with controller-side speed blending,
  pinned at zero speed and at the classic reference amplitude. Add run/fly/swim
  clips only where source states require them.
- Tier 1: the same visible clips, but feed the authoritative hitbox pose from the
  synced movement/controller state and time. If a deterministic server evaluator
  cannot match the visible bones, retain the current hitbox and stop.
- Molang `query.ground_speed` is allowed only if its numeric mapping is verified
  against `limbSwingAmount`. Custom code-driven bones are a last resort because
  artists cannot edit them.

### State-branching

Split each source branch (`getAttacking()`, flying, sitting, wet, variant, and so
on) into a named clip/state. Drive transitions from server-synced entity data;
client-only guesses may affect decoration but never damage geometry. Follow the
Queen Movement controller pattern: an exclusive priority order, explicit STOP for
terminal state, and documented trigger keys.

Loop-mode review is mandatory. Every trigger-fired one-off declares `loop: false`;
`thenPlay` does not force one-shot behavior. `hold_on_last_frame` is permitted only
for a deliberate terminal death/corpse pose. This directly carries BUG-035 forward
and must become a mechanical G4 audit.

### FK-chained

Alien and EmperorScorpion must become real parent-child bone hierarchies rather
than a flat rig whose child pivots are rewritten by trigonometry. Preserve part
names, derive pivots in Blockbench terms, and compare independently evaluated
world transforms at every chain link. Schedule them only after simple and
gait-scaled conversions prove the toolchain. Do not revive the early Queen helper's
synthetic/fake hierarchy approach.

### Existing solver and Queen exceptions

SpiderRobot/AntRobot retain procedural IK and must never be keyframe-baked. Queen
is not regenerated: her eight clips and controllers are reviewed only as the
known-good contract. Her one-offs remain `loop: false`; death deliberately holds.
